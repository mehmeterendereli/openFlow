# Local MusicGen Setup Notes

openFlow now uses `facebook/musicgen-small` through Meta AudioCraft. The model is
loaded lazily on the first generation request, cached in the FastAPI process, and run
on CUDA whenever `torch.cuda.is_available()` is true. If CUDA is unavailable, the
adapter selects CPU automatically; CPU generation is functional but substantially
slower.

## Important compatibility facts

- AudioCraft's official installation guide specifies Python 3.9 and PyTorch 2.1.0.
- AudioCraft recommends installing PyTorch before AudioCraft (especially because of
  `xformers`) and requires/recommends FFmpeg for audio handling.
- `facebook/musicgen-small` is the 300M parameter model. Meta notes that smaller GPUs
  can run short sequences with this model; start with 4 seconds before trying 30.
- AudioCraft code is MIT, while released model weights use CC-BY-NC 4.0. Confirm that
  license fits the intended publishing/commercial use.

Official references:

- https://github.com/facebookresearch/audiocraft#installation
- https://github.com/facebookresearch/audiocraft/blob/main/docs/MUSICGEN.md
- https://docs.pytorch.org/get-started/locally/

## Recommended Windows setup: WSL2 + NVIDIA CUDA

Native Windows installation can fail when transitive AudioCraft packages do not ship
matching Windows wheels. WSL2 Ubuntu gives the closest environment to AudioCraft's
documented Linux setup.

1. Install the current NVIDIA Windows driver with WSL CUDA support.
2. In PowerShell, install WSL2 if needed: `wsl --install -d Ubuntu`.
3. Inside Ubuntu, confirm the GPU is visible: `nvidia-smi`.
4. Install system tools:

   ```bash
   sudo apt update
   sudo apt install -y \
     ffmpeg build-essential git pkg-config \
     libavcodec-dev libavdevice-dev libavfilter-dev libavformat-dev \
     libavutil-dev libswresample-dev libswscale-dev
   ```

5. Create the Python 3.9 environment and install openFlow's AI dependencies:

   ```bash
   make setup-ai
   ```

6. If the generic PyTorch wheel does not expose CUDA, activate `.venv-musicgen` and
   reinstall `torch` and `torchaudio` using the command generated by PyTorch's official
   **Start Locally** selector for the installed driver/CUDA platform. Then reinstall
   `audiocraft`.
7. Verify CUDA before starting the API:

   ```bash
   .venv-musicgen/bin/python -c \
     "import torch; print(torch.__version__, torch.cuda.is_available(), torch.cuda.get_device_name(0) if torch.cuda.is_available() else 'CPU')"
   make backend-ai
   ```

The first request downloads model weights. Set `AUDIOCRAFT_CACHE_DIR` to move the
AudioCraft cache. Keep enough free disk space for weights and package caches.

If sudo access is unavailable, use a user-space Conda/Micromamba environment.
Installing PyAV as a conda binary avoids its system-header build step:

```bash
micromamba create -y -p ~/.local/share/openflow-musicgen -c conda-forge \
  python=3.9 pip pkg-config av=11 'spacy>=3.6.1,<3.8' 'numpy<2'
micromamba run -p ~/.local/share/openflow-musicgen \
  python -m pip install -r backend/requirements.txt
micromamba run -p ~/.local/share/openflow-musicgen \
  python -m uvicorn backend.app.main:app --reload --port 8000
```

The development headers and `PKG_CONFIG_PATH` are required only when PyAV must build
from source. AudioCraft pins PyAV 11, which has no compatible pip wheel on some
Python/platform combinations.

`backend/musicgen-constraints.txt` captures AudioCraft's documented PyTorch 2.1.0
target and holds spaCy below 3.8 so dependency resolution remains compatible with
Python 3.9. It also holds Transformers below 4.40 because newer releases require
PyTorch pytree APIs that are absent from 2.1. The required `torch`, `torchaudio`, and
`audiocraft` entries remain in `backend/requirements.txt`.

## Device control and recovery

- `OPENFLOW_MUSICGEN_DEVICE=auto` (default): CUDA first, otherwise CPU.
- `OPENFLOW_MUSICGEN_DEVICE=cuda`: request CUDA, but safely falls back to CPU when CUDA
  is not detected.
- `OPENFLOW_MUSICGEN_DEVICE=cpu`: force CPU inference.

If a generation returns HTTP 500 with an out-of-memory message, the FastAPI process
remains alive and clears the CUDA allocator cache. Reduce duration, close other GPU
applications, or force CPU. Generated WAV files are 32 kHz PCM and feed directly into
the existing FFmpeg render endpoint.
